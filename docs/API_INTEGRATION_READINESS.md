# API integration readiness

Source audit: 22 October 2026. This is an integration checklist, not evidence that a deployed backend supports every existing service. No endpoints were added or called during this work.

## Shared foundations

- General loading: `src/components/ui/AppLoader.tsx` owns page, fullscreen, inline and compact presentation. Session verification and lazy routes share it. Admin dashboard/list skeletons, table skeletons and content-specific previews remain distinct.
- Every Customer, Vendor, Vendor Staff and Admin feature requires `AuthGuard` plus its existing exact-role `RoleGuard`. Former Customer review pages and the Vendor static shell are private again. No Admin-wide inheritance or Vendor Staff access to Vendor routes was added. Login/signup retain `GuestGuard`; legal/help/403 pages remain public.
- Review/mock identity flags and role selection were removed from runtime configuration. Existing local environment files are unchanged; obsolete variables in them have no effect. Static fixtures never provide authenticated identity.
- Auth still persists tokens through `sessionStorageService`, verifies identity using the existing current-user flow, and gates restored identities until verification completes. Refresh remains bounded and concurrent requests share a refresh. Only the established definitive rejection policy clears credentials; temporary failures retain retryable, unverified sessions.
- RTK Query uses `baseApi` / `authBaseQuery` / `rawBaseQuery` under `src/services/api`. Base URL is `VITE_API_BASE_URL`, with the existing `/api` fallback; socket URL is `VITE_SOCKET_URL`. Both are public configuration, never secrets. Existing code adds bearer headers centrally. No second client, API slice, global loading state or permission hierarchy was added.
- Logout and session replacement clear API caches and disconnect sockets. Identity/role changes within a session now do the same. Local page reducers/forms remain component-owned; fixtures do not write authenticated server state.
- Keep `AppError`, `normalizeApiError`, field-error mapping, `ErrorState`, Sonner and the error boundary. Existing mappings cover 400/422 validation, 401 authentication, 403 authorization, 404 missing resources, 409 conflict, 429 throttling, network/timeouts and sanitized server errors. Resource retries and pending/duplicate-submit behavior should survive integration.

## Reading the checklist

**API** means an existing RTK Query connection in source; **local** means fixtures/React state; **mixed** means API reads with unfinished local actions. **Placeholder** means the frontend workflow is not complete. These labels do not assert live backend availability.

All pending operations below are **Backend contract required**: confirm request/response models, ownership, validation, pagination, money/date semantics and errors before replacing fixtures. Existing UI models are not proposed backend DTOs. Priorities: **P0** session prerequisites, **P1** core workflows, **P2** secondary/unfinished workflows.

Model/data paths below are relative to `src/features/<role>/`. All rows require the named role exclusively unless marked public/guest.

## Next integration steps and limits

1. Confirm the P0 session contracts, then the P1 resource contracts with backend owners. Frontend guards do not authorize backend data; every backend endpoint must independently enforce identity, role and ownership.
2. Add confirmed endpoints to feature API modules through `baseApi.injectEndpoints`. Adapt responses into the existing UI types; retain local drafts, selection, dialogs, validation, previews and responsive markup. Do not copy query results into ordinary Redux slices.
3. Confirm list envelopes/server pagination, resource IDs, upload limits/storage, timezones, currency precision, action permissions and errors. No new endpoint URLs or request bodies are proposed here.
4. Replace local previews only when delivery/persistence is real. Preserve object-URL cleanup and avoid uploading through presentation components. Central Socket.IO scaffolding exists but no completed feature consumes `useSocket`; event/auth/reconnection contracts remain required.
5. Manual QA remains necessary for sign-in/return navigation, role-specific 403s, reload/retry/logout, layout/typography, keyboard focus, responsive overflow and preserved feature flows. Automated validation is server-free; no browser, development server or live API was used. Existing refresh/token contracts and unfinished placeholder screens remain external dependencies.
