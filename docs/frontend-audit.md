# Frontend API integration audit

Audit date: 2026-10-27 (Asia/Dhaka). Scope: the current working trees of `christinacormie-web` and sibling `christinacormie-backend`. This is source inspection, not a deployment or runtime certification. Only the four requested Markdown deliverables were created. Existing uncommitted changes were included as audit evidence and preserved.

Read alongside [verified mapping](frontend-backend-api-mapping.md), [implementation plan](frontend-api-integration-plan.md), and [gaps](api-integration-gaps.md).

## Counting and evidence rules

A route means a distinct routable URL pattern or index destination, not every pathless guard/layout object. There are **37 screen URL patterns**, **15 redirect destinations**, and **1 wildcard**, totaling **53 route outcomes**. `/profile/me` and the sample member/truck URLs are values of `/profile/:id`, not additional route patterns. The router error boundary is not a separate URL. The vendor parent and its index render one home screen.

API-dependent feature counts use the numbered operation groups in the mapping, not buttons, endpoint declarations, or pages. A group may require several endpoints. Local presentation controls and backend-only capabilities are excluded from that denominator. `INTEGRATED` means wired to an actual matching source contract; it does not mean live tested. `BROKEN` takes precedence over `PARTIAL` where a concrete contract mismatch affects the group. Missing runtime evidence is called out separately.

Status meanings: INTEGRATED = real API call with a source-supported contract; PARTIAL = live wiring or only part of a workflow; MOCK = fixtures/local previews stand in for server operations; STATIC = placeholder/unwired server capability; LOCAL_ONLY = deliberately client-side; BROKEN = verified source mismatch; UNVERIFIED = insufficient evidence. Intentional Stage A previews are not themselves defects.

### Environment and infrastructure verdict

The active `.env` API URL is absolute HTTPS with path `/api/v1/`; hostname/value was not copied into these reports. `env.ts` trims its trailing slash. No socket URL key was found in that file. `.env.example` leaves both public configuration keys empty. `baseQuery.ts` falls back to `/api`; `vite.config.ts` has no proxy. Thus the active configured prefix agrees with backend controller prefixes, while an unconfigured deployment does not automatically work. Document deployment configuration in a later authorized task; do not edit this user's environment.

Bearer headers and JSON accept headers already work. RTK Query's standard object argument serialization is retained; no demonstrated need for a custom serializer. Arrays and domain filters must be mapped to the exact DTO representation before querying. Multipart requests must leave Content-Type boundary generation to the browser. No timeout is configured; choose one only with an agreed operational requirement.

Refresh parses `accessToken`/`refreshToken` from the backend response; it need not infer expiry units. The current backend auth service returns no explicit expiry field; frontend optional `expiresAt` is therefore not populated by that response. Reactive 401 refresh is the current strategy. Staff vendor-profile/QR routes have a separate owner-lookup defect (G13), despite admitting the role in guards. Manual logout only clears local credentials and never calls the implemented revocation endpoint. Session failure handling distinguishes refresh 401 from network/server failure; retain this behavior and its regressions.

### Redirect and fallback inventory

`/` redirects to `/dashboard`; `/dashboard` redirects to the verified role home; `/dashboard/customer` redirects to `/discover`. `/terms-condition` and `/terms-of-service` redirect to `/terms-and-conditions`.

Ten legacy admin URLs redirect to the corresponding `/dashboard/admin...` URL: `/admin-dashboard`, `/admin-dashboard/dashboard`, and `/admin-dashboard/{bookings,vendors,users,community,reviews,rewards,payments,settings}`. These redirects still land behind AuthGuard/RoleGuard. `*` renders NotFoundPage. Sources: `app.routes.tsx`, `public.routes.tsx`, `customer.routes.tsx`, `getRoleHomeRoute.ts`.

## Local-only behavior to preserve

Tabs, dropdown expansion, modal/lightbox open/close, form draft editing, keyboard/focus handling, image preview URLs, clipboard/native share invocation, pagination presentation and URL query state remain client concerns. They should not acquire backend mutations. Share counters, persisted favorites/follows, real QR identity and durable saved drafts are separate server concerns. Clearing local message previews is client-only; deleting durable conversation history is not supported by an identified endpoint.

## Validation and limitations

This documentation task did not run builds, application tests, servers, browsers, screenshots or production requests. Source parsing, inventory/controller comparison, document formatting, local-link checks and whitespace review are the applicable verification. Source-supported failures are distinguished from suspected race/operational issues in the gaps document. Existing tests were inspected for planning, not claimed as rerun. The four requested documents were formatted with the installed Prettier; all 1,728 local document/source links resolved, including source-line bounds. The final changed-file formatting and whitespace checks are reported at handoff.

The backend inventory contains 281 HTTP endpoints; parsing current controller decorators also found 281, with no method/path additions or omissions. Inventory prose is not enough to establish response shapes: service/repository selections, presenters, DTOs and Prisma models are linked in the mapping. Runtime data, deployment CORS, third-party configuration and financial settlement remain unverified.
